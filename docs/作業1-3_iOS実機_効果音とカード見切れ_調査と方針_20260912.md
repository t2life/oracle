### 2.1 ① シャッフルの効果音

#### 呼び出し側 — `mobile_app/lib/features/shuffle/presentation/shuffle_screen.dart` L118-132

#### 再生側 — `mobile_app/lib/core/audio/sound_service.dart` L69-79

```dart

  ...
    await _effectPlayer.stop();
    await _effectPlayer.play(AssetSource('sounds/${sound.fileName}'));
  ...
}
```

#### 素材 — `mobile_app/assets/sounds/shuffle.wav`

| 項目 | 値 |
|---|---|
| 長さ | **280ms**（22,050Hz・モノラル・16bit） |
| 生成元 | `scripts/generate_sound_assets.py` `gen_shuffle()` → `_noise_swish(0.28, 0.42)`（ノイズを整形した擦過音） |
| 170ms 時点の振幅 | 20ms 窓の RMS がほぼ最大（約 4,800／最大 5,179）＝**音の山の途中** |

#### ①の原因

1. 指を動かし続けると **170ms ごとに `stop()` → `play()`** が走る。
   280ms の音は毎回 **6割のところ（振幅が最大付近）で切られる**。
   波形の途中で切ると「プツッ」というクリックが出て、切り刻まれたノイズになる。
2. `SoundService.ensureLoaded()` は `PlayerMode.lowLatency` を指定しているが、
   **iOS 版プラグインでは何もしない**
   （`audioplayers_darwin` 6.5.0 `AudioplayersDarwinPlugin.swift`: `setPlayerMode` は
   「no-op for darwin; only one player mode」）。
   iOS は AVPlayer 1本で、`stop()`（一時停止＋先頭へのシーク）→ `play()`（再開）を
   毎回プラットフォームとの往復で行うため、**鳴り始めの遅れが一定しない**。
3. Android は同じ指定で `SoundPool`（低遅延の短音専用）を使う
   （`audioplayers_android` `WrappedPlayer.kt`: `LOW_LATENCY -> SoundPoolPlayer`）。
   ∴ 同じ Dart コードでも、Android では目立たず iOS で表に出た。

`chime` / `whoosh` / `flip` / `tap` は単発の呼び出しで、**連続して打ち切られるのはシャッフルだけ**
（`SoundService.instance.play` の呼び出し元を全件確認）。

### 3.1 ① 効果音 — 同じ音は鳴らし切る

**変更するファイル**: 2つ（新規クラス・新規ファイルなし）

  既定値は `true`（**現行どおり打ち切って鳴らし直す**）。
  `false` のときは、**同じ音がまだ鳴っていれば何もしない**。
  判定には、プレイヤーが既に持っている `state` と `source` をそのまま使う（新しい状態は持たない）。

**得られる挙動**:

- 枠が札より広い端末（幅 390 なら枠 219×336、札 196×336）では、札は**原寸・比率どおり**に中央に置かれ、左右に少し余白が出る。

- 「両隣の札を少し覗かせる」（`viewportFraction: 0.66`）という既存の意図は変わらない。

#### ②で採らなかった案

| 案 | 採らない理由 |
|---|---|
| `LayoutBuilder` で `viewportFraction` を幅から計算する | 行数が増える割に得るものが同じ。覗かせ具合が端末ごとに変わる |
| 図柄を `BoxFit.contain` にする | 共通部品（全画面の札）の変更になり影響が広い。原因は枠の側にある |
| `_width` を画面幅から計算する | 札の高さ（`SizedBox`）との二重管理になる |
