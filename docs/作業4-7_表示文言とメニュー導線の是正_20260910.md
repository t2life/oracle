## 2. ①③ ルビ・属性・エレメント（マスタから画面まで）

読み・属性分類・エレメントは **44柱.xlsx の「44柱一覧」に元からあり**、
`import_card_db.py` も `reading` / `attribute` / `element` として取り込んでいたが、
`Card` モデルから先へ**一度も渡っていなかった**（取り込んだきり死蔵）。
その経路を通した。

```text
44柱.xlsx →(import_card_db)→ card_content.json →(store)→ Card
  → ResultCard →(api)→ /reading/* の cards[]        → アプリ
  → CardResponse →(api)→ /cards                     → アプリ
  → export_master_assets → master_data.json         → オフライン
```

表示は次のとおり。

- 札面（結果・カード確定演出）: 神名の下に小さく「（アメノミナカヌシ）」。
  括弧書きを神名と同じ行へ混ぜると札が窮屈になるため行を分けた。
- 結果のカード情報行: 「属性：別天神/創造神　エレメント：エーテル」。
- ポジション別カード（複数枚）: 「天之御中主神（アメノミナカヌシ）」＋属性・エレメント。
- ルビは**日本語表示のときだけ**付ける（読み仮名は日本語話者向けのため）。
  属性・エレメントは全言語で出す（見出しのみ翻訳）。

## 3. ② 導入句の変更

「そっと差し出されているのは」は**優しいトーンの導入句**（接続表現マスタ）で、
文章そのものではなくマスタの1セル。`extend_reading_db.py` の定義を
「降りてきた託宣は」へ変更し、DB → import → export の順で反映した。

あわせて**パリティ期待値の作り直しをスクリプト化**した
（`scripts/build_parity_fixture.py`・新規）。従来は手作業だったため、
素材を変えるたびに Dart 実装との突き合わせが取り残される恐れがあった。

さらに、期待値の生成条件（`date_key` / `session_id`）を期待値ファイル自身に
持たせ、Dart 側のテストがそれを読むようにした。以前は両者に別々の値が
直書きされており、**片方を変えると日替わり選択のハッシュがずれて偽の不一致**になる
（今回実際に踏んだ）。

## 4. ④ プラン購入画面

- `planSubscription` の表示名を「サブスク会員」→**「月額有料プラン」**へ統一
  （en: Monthly plan／zh: 月度付费方案）。画面によって呼び名が違う状態を解消。
- 全機能が解放済みのプランでは購入項目を**選べない（グレー表示）**にし、
  「有料プランのため、すべての機能が解放されています。」を出す。
- 判定は `planUnlocksAllFeatures(plan)`（`plan_l10n.dart`）に集約した。
  対象は**月額有料プランと管理者のみ**。チケットは「回数の購入」であって
  機能解放ではないため、チケットプランの利用者は従来どおり購入できる。

## 6. 機種引継ぎコード（⑤の1項目・新規機能）

「引継ぎコード発行」はリンクではなく機能のため、実装した。

- 旧端末で発行 → 新端末で入力、の2操作でアカウント（プラン・チケット・履歴）を移す。
- コードは **12文字・4文字区切り・使い捨て・既定7日間有効**。
  見間違えやすい `0 O 1 I L` を使わない。
- **発行し直すと前のコードは無効**（紛失時に締め直せる）。
- 未知のコードと期限切れは**同じ文言**で断る（存在の有無を入力側に教えない）。
- アカウントの付け替えはサーバー処理のため、オフラインでは使えない旨を表示する。

| ファイル | 内容 |
|---|---|
| `config.py` | `TransferCodeRules`（文字種・長さ・区切り・有効時間） |
| `models.py` | `TransferCode`（発行元・発行日時・期限・使用日時） |
| `store.py` | 保存／取得／使用済み記録（同一ユーザーの未使用コードは1本だけ残す） |
| `services/auth_service.py` | `issue_transfer_code` / `redeem_transfer_code` / 入力の正規化・表示整形 |
| `api.py` | `POST /account/transfer-code`・`POST /account/transfer-code/redeem` |
| `features/transfer_code/presentation/transfer_code_screen.dart` | 発行・コピー・引き継ぎの画面 |

### 前提として直したこと（重要）

アプリのユーザーIDが `mobile_demo_user` 固定で、**全端末が同じアカウント**だった。
これでは引き継ぐ先が存在しないため、初回起動時に端末ごとのIDを1つ作って
`SharedPreferences` に保存する方式へ変更した。

**影響**: 今回のビルドを入れた既存端末は、保存済みIDが無いため
**新しいアカウントとして始まる**（サーバーが再起動で消えるインメモリ運用のため
実害はないが、既存のチケット残数・履歴は引き継がれない）。
