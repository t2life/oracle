## 2. 実装

### 2.1 マスタ（オーナーのxlsx編集は不要）

| シート | 内容 |
|---|---|
| `番号解釈マスタ`（新規・5行） | エレメント／単位／上限／定型文／超過時の定型文／数量の定型文 |
| `番号解釈キーワード`（新規・18語） | 区分（時期・数量）／キーワード |

**文面もマスタが持つ**ため、言い回しの調整にアプリ更新が要らない。
既存シートには触れていないので、オーナーのDB更新と衝突しない。

### 2.2 文章への組み込み

`compose_reading` の段落を1つ増やしただけで、**新API・新画面は無い**。

```text
導入 → 各カード → 組み合わせ → 文脈 → [番号の読み] → 行動提案 → 締め
```

判定と組み立ては `InterpretationEngine` に閉じており、文章の責務を分散させていない。

### 2.3 オフラインとの一致

Dart の `InterpretationComposer` へ**同じ手順を移植**した。
パリティ用の期待値に「時期を問う」「数量を問う」2ケースを追加し、
**サーバーとオフラインで一字一句同じ文章になること**をテストで固定した。
片方だけ直すとこのテストが落ちる。

### 2.4 画面（ご指摘）

拡大画面の閉じる操作が、暗い背景に埋もれた「✕」アイコンだけで見つけられなかった。
→ **「閉じる」を太字の文字で、黒い下地の上に**置いた（アイコンも併記）。
札の外をタップしても閉じられる点は従来どおり。

## 6. 3大リスクの最終サマリー

### 占いとしての妥当性

1. 外れの目立ちやすさ → 「およそ」「目安」で断定しない。禁止表現テストで全文を走査
2. 神格と無関係な数字の押しつけ → 問われたときだけ出す（テスト2・8）
3. 非現実的な年数 → 上限を超えたら数字を出さない（テスト5）

### システム

1. マスタ未整備 → 対応表が無ければ段落を出さない（fail-soft）
2. サーバーとオフラインの食い違い → パリティテストで一字一句を固定
3. 判定語の取りこぼし → 出ないだけで壊れない。語はマスタで足せる

### 運用

1. 図柄とマスタの番号の不一致 → **表示を実装していない**ため利用者に見えない
2. 文面の調整 → マスタの定型文を直すだけ。アプリ更新は不要
3. 語の追加 → `番号解釈キーワード` に行を足すだけ
