# iOS移植・ビルド手順（Mac作業者向け）

## 1. 文書情報

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-09-07 |
| 対象 | `mobile_app`（Flutter）をiPhone（iOS）でビルド・実行する担当者 |
| リポジトリ | <https://github.com/t2life/oracle> |
| 前提 | 本アプリのDartコードは**クロスプラットフォーム**で、Android版と**同一のソース**がiOSでもそのまま動作する。Windows側でiOSプラットフォーム足場（`mobile_app/ios/`）とiOS固有設定は生成・投入済み。**iOSの実ビルド・署名・実機/シミュレータ実行はmacOS + Xcodeが必須**のため、以下はMacで行う |

## 2. Windows側で完了済みの内容（このリポジトリに含まれる）

- `mobile_app/ios/` 一式（`flutter create --platforms=ios --org com.apps2craft` で生成）。
- Bundle Identifier: **`com.apps2craft.oracleMobileApp`**（Androidの`com.apps2craft.oracle_mobile_app`に対応）。
- `ios/Runner/Info.plist` に投入済みのiOS固有設定:
  - `CFBundleDisplayName` = **日本神話オラクルロンカード**（ホーム画面のアプリ名）。
  - `NSPhotoLibraryUsageDescription`（⑤ユーザー画像テーマで写真ライブラリを開くために必須）。
  - `NSAppTransportSecurity → NSAllowsArbitraryLoads = true`（**開発用**。ローカルLANサーバー`http://`接続のため。**本番はHTTPS化して本ブロックを削除**）。

## 3. Macでの初回セットアップ

```bash
# 前提: Xcode / CocoaPods / Flutter SDK 3.47系 が導入済み
git clone https://github.com/t2life/oracle.git
cd oracle/mobile_app

flutter pub get          # 依存解決（Podfileはこの後の初回ビルドで自動生成）
cd ios && pod install && cd ..   # CocoaPods依存の解決
```

## 4. 署名（Xcode）

```bash
open ios/Runner.xcworkspace   # .xcodeproj ではなく .xcworkspace を開く
```

- Runner ターゲット → Signing & Capabilities → Team を自分のApple Developerチームに設定。
- 必要なら Bundle Identifier を運用値へ変更（既定`com.apps2craft.oracleMobileApp`）。
  変更した場合はAndroidの`applicationId`との対応をストア申請時に整理する。

## 5. ビルド・実行（Android版と同じdart-define）

接続先・有料解放フラグはAndroidと完全に同一の指定を使う。

```bash
# シミュレータ/実機で起動（開発・LANサーバー接続）
flutter run \
  --dart-define=ORACLE_API_BASE_URL=http://<PCのIP>:8000

# 有料機能解放版で確認したい場合
flutter run \
  --dart-define=PREMIUM_UNLOCKED=true \
  --dart-define=ORACLE_API_BASE_URL=http://<PCのIP>:8000

# リリースIPA（配布用・要署名）
flutter build ipa \
  --dart-define=ORACLE_API_BASE_URL=https://<本番APIのドメイン>
```

- `ORACLE_API_BASE_URL` 未指定時の既定は `http://127.0.0.1:8000`（iOSシミュレータはMac自身のlocalhostを指すため、Mac上でバックエンドを起動していれば既定でも到達する）。
- サーバー未到達時は**自動でオフラインモード**に切替わり単体動作する（Android版と同一挙動）。

## 6. Android版との差分・パリティ表

| 項目 | Android | iOS | 状態 |
|---|---|---|---|
| Dartソース(`lib/`) | 共通 | 共通 | 同一 |
| アプリ表示名 | `AndroidManifest.xml` label | `Info.plist` CFBundleDisplayName | 両方「日本神話オラクルロンカード」 |
| 開発用HTTP許可 | `usesCleartextTraffic=true` | `NSAppTransportSecurity` | 両方**本番HTTPS化で削除**すること |
| 画像選択権限 | ランタイム権限 | `NSPhotoLibraryUsageDescription` | 両方投入済み |
| 効果音(audioplayers) | ○ | ○ | 対応（実素材差替えは`assets/sounds/`同名WAV） |
| 有料解放/接続先 dart-define | 同一 | 同一 | パリティ |

## 7. 既知の未対応（Android/iOS共通・スコープ外）

- Apple/GoogleのネイティブサインインSDK統合は未実装（`/auth/apple`・`/auth/google`のAPIは存在）。iOSでは特に **Sign in with Apple** がストア審査で要求される場合があるため、公開前に統合要否を判断する。
- FCM/APNsの実プッシュ配信は未接続（ロードマップB-3）。iOSはAPNs証明書/キーの準備が別途必要。
- カード絵柄・実効果音・オープニング動画は差替えの受け口のみ実装済み（`oracle_card_visuals.dart`・`assets/sounds/`）。

## 8. 同期運用（今後）

- **単一ソース**はGitHub `t2life/oracle`。Windows(Android)側とMac(iOS)側は本リポジトリを介してpull/pushで同期する。
- Dartコード・ARB・アセットの変更は双方に自動反映される（プラットフォーム共通）。プラットフォーム固有ファイル（`android/`・`ios/`）のみ各OSで個別管理。
- マスタ変更時の手順（Android版から継続）: DBのxlsx更新 → `scripts/import_card_db.py` → `scripts/export_master_assets.py` → 各OSで再ビルド。
