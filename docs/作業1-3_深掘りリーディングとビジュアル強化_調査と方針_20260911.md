# 第1部 深掘りリーディング

## 1.1 決定事項（2026-09-11 承認済）

| # | 決定 |
|---|---|
| 1 | 枚数は**選ばせる**（3／5／7枚） |
| 2 | **一律チケット5枚** |
| 3 | **月額プランは無制限** |
| 4 | 託宣と深掘りは**履歴1件**にまとめる |

## 1.2 業界の作法に沿わせる — 「引き直し」にしない

タロット／オラクルの実務では、**同じ問いへの引き直し**は読みが成立しないため戒められる。
認められる深掘りは「出たカードを**起点として引き継ぎ**、そこから広げる」形である。

∴ 設計の核は次の1点に集約する。

> **託宣で出たカードを1枚目として引き継ぎ、残りを追加で引く。**

```text
本日の託宣（無料・1枚・相談内容なし）
   └ 深掘り（チケット5枚／月額は無制限）
        ├ 枚数を選ぶ（3／5／7）
        ├ ここで初めて相談内容を入力する
        ├ 託宣のカードを 1枚目として引き継ぐ   ← 引き直しにしない要
        └ 追加で 2／4／6 枚を引き、合計で読む
```

託宣は「今日の指針」であり問いを持たない。深掘りで初めて問いが立つ流れは実務の感覚と一致する。

## 1.3 実装方針（新しい仕組みを作らない）

### 既存のスプレッドをそのまま使う

`three` / `five` / `seven` は既に **5チケット・対象プラン ticket,subscription** で定義済み。
月額無制限も `BillingService.consume_for_spread` が
**チケットプラン以外では消費しない**既存実装でそのまま成立する。

∴ **マスタに行を足さない。課金の分岐も増やさない。**

### 変更点は「起点の引き継ぎ」1つ

| ファイル | 変更 |
|---|---|
| `schemas.py` | `StartReadingRequest` に `origin_session_id: str \| None` |
| `models.py` | `ReadingSession` に `origin_session_id`、`ReadingResult` に同項目 |
| `services/reading_service.py` | `start_session` が `origin_session_id` を受け、元結果の**1枚目のカードIDを `selected_card_ids` の先頭へ固定**する。引く枚数は `draw_count - 1` になる |
| `api.py` | 既存の `/reading/start` に項目が1つ増えるだけ。新エンドポイントなし |

カード選択画面は「残り n 枚」を引く。1枚目は**既に確定している**ため選ばせない。

### 履歴を1件にまとめる（決定4）

深掘りの結果を保存するとき、**起点の託宣の履歴があれば削除して置き換える**。
本文は「託宣の文章＋深掘りの文章」を1件に収める。

> 託宣結果で「履歴に保存」を押してから深掘りする利用者がいるため、
> 単に追加すると2件になる。置き換えで1件を保つ。

### 画面

**新規画面は作らない。**

| 画面 | 変更 |
|---|---|
| U-09 結果 | 「ディープリーディング」ボタンを、枚数選択へ進む導線にする（託宣の結果のときだけ出す） |
| 既存のスプレッド選択 | 起点ありのときは「3／5／7」だけを出す（フリーは起点と枚数の整合が取りにくいため外す） |
| 既存のテーマ＋相談内容 | そのまま流用。テーマは託宣のものを初期値にする |
| 既存のシャッフル・山選択・カード選択 | そのまま。カード選択だけ「残り n 枚」表示 |

### 画像生成のプロンプトは、ほぼ揃っている

| 確認 | 結果 |

## 2.2 方針

### A. カードの絵柄

**画像はファイル名の規約で引く。マスタに列を足さない。**

```text
assets/cards/{card_id}.webp     例: assets/cards/japanese_mythology_card_001.webp
```

- `card_id` は既にマスタが持つ一意キーで、**新しい項目を増やさずに済む**。
- **絵が無いカードは今の文字カードへ自動で落ちる**（`OracleCardFace` を
  「画像があれば画像、無ければ文字」に変える）。
  ∴ **1枚も揃っていない現時点で入れても壊れない。**揃った順に絵が出る。

表示箇所と大きさ。

| 画面 | 出し方 |
|---|---|
| U-09 結果（代表カード） | 大（現行の札面と同じ位置・幅196） |
| U-09 ポジション別 | **小（幅56の縮小図）を各行の左へ**（ご指摘の「縮小したカード図柄」） |
| U-08 カード展開 | 裏面は現行のまま。確定時のフリップで表面に絵が出る |
| U-12 カードライブラリ | 一覧に縮小図（テキスト一覧から絵の一覧へ） |
| U-10 履歴 | 各行の左に縮小図 |

### B. キャラクターのワンポイント

ホーム画面の世界観を各画面へ広げる。

```text
assets/character/{場面}.webp    例: assets/character/result_joy.webp
```

- 添付の**白黒12表情**をカラー化し、**構図を変えてワンポイント**にする。
- 配色は添付の**大人キャラ**（金髪／赤・黒・金の装束）に従う。
- 置き場所の案（各画面1点まで。テキストの邪魔をしない位置）。

| 画面 | 表情 | 位置 |
|---|---|---|
| U-09 結果 | 穏やか／喜び | 見出しの横に小さく |
| U-06 テーマ＋相談内容 | 考え中 | 入力欄の上 |
| シャッフル | 集中 | 案内文の横 |
| 履歴が空のとき | 困り顔 | 空表示の中央 |
| 通信できないとき | 困り顔 | 同上 |

**カードと同じく、無ければ出さない**（あとから足せる）。

### C. 私にできること・できないこと

| | 担当 |
|---|---|
| 画像そのものの制作 | **私にはできない**（画像生成の手段を持たない）。オーナー作業または外部ツール |
| 生成用プロンプト一覧の書き出し | **可能**。`scripts/export_card_art_prompts.py` を作り、44柱ぶんの
（card_id／神名／属性／エレメント／Positive／Negative／スタイルタグ／出力ファイル名）をCSVで出す |
| 画像の仕様決め（寸法・形式・命名） | 可能 |
| アプリへの組み込みとフォールバック | 可能 |
| 大年神の1柱のプロンプト起草 | 可能（他43柱の書き方に合わせて作る。**内容の承認は必要**） |

### D. 画像の仕様（案）

| 項目 | 案 | 理由 |
|---|---|---|
| 形式 | WebP | PNGより小さく、Android/iOSとも対応 |
| カード寸法 | 幅 800px・縦横比 1:1.55 | 現行の札面と同じ比率。拡大表示に耐える |
| 1枚あたり | 100KB 以下 | 44枚で約4MB。現在のAPK 58MBに対し許容 |
| キャラ | 幅 400px・背景透過 | ワンポイント用 |

# 3. リスク

## 3.1 金銭・課金

1. 深掘りで二重課金 → セッション開始は1回で、既存の消費経路をそのまま使う
2. 起点の託宣が無料枠なのに深掘りが無料で通る → `three/five/seven` の対象プラン判定が既に効く
3. 月額の無制限が効かない → `consume_for_spread` はチケットプラン以外を消費しない（既存挙動をテストで固定する）

## 3.2 システム

1. 1枚目を引き継ぎ損ねて引き直しになる → 起点カードが結果の1枚目であることをテストで固定
2. 履歴が2件に増える → 置き換えの規則をテストで固定
3. 画像が無いカードで画面が割れる → **無ければ文字カードへ落ちる**実装を先に入れ、絵は後から足す

## 3.3 運用

1. 絵柄が44枚揃うまで見た目が不揃い → 揃った順に反映される。一斉公開の必要はない
2. アプリ容量の増加 → WebPと寸法上限で抑える。実測して報告する
3. 大年神の1柱だけ絵が作れない → プロンプトを起草し、承認後に生成
