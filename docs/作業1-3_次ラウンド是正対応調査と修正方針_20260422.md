### 3.3 根本原因（コードレベル）

1. U-12/U-14/U-15/U-16 は骨格作成後に state/API統合が未実施。
2. `app_state.dart` の対象ドメインが占い中心で、カード辞典・外部導線用の状態を保持していない。
3. `ApiClient` が backend 既存エンドポイントの一部しかラップしていない。
4. `PostgresPersistence` の責務が結果/履歴のみで、ユーザー・課金状態・告知・問合せの永続化経路が存在しない。
5. 監査ログが標準ログ出力のみで、操作追跡の抽出性が弱い。
6. CI と監視の設定ファイル未整備により運用自動検証が不足。

## 4. 作業3 修正方針（実装前）

### 4.1 方針A: モバイル未完4画面を app_state + 実APIで本実装

変更対象（予定）:

- `mobile_app/lib/core/models/domain_models.dart`
- `mobile_app/lib/core/network/api_client.dart`
- `mobile_app/lib/core/state/app_state.dart`
- `mobile_app/lib/features/card_library/presentation/card_library_screen.dart`（U-12）
- `mobile_app/lib/features/ron_room/presentation/ron_room_screen.dart`（U-14）
- `mobile_app/lib/features/shop/presentation/shop_screen.dart`（U-15として整合）
- `mobile_app/lib/features/consultation/presentation/consultation_screen.dart`（U-16として整合）
- `mobile_app/lib/features/home/presentation/home_screen.dart`（導線文言/遷移整合）
- `mobile_app/pubspec.yaml`（外部URL起動依存）

実装方針:

- 既存 `OracleAppState` を拡張し、カード検索・デッキ絞込・外部リンク一覧・配信一覧を保持。
- APIは backend 既存 `/cards`, `/links/shop`, `/links/consultation`, `/links/live`, `/links/live-events` をそのまま利用（契約変更なし）。
- エラー/ローディング/空データ時のフォールバック文言を全4画面で実装。
- 外部遷移は `url_launcher` で明示実装し、失敗時は Snackbar 等で通知。
- analytics 既存イベント（`shop_link_clicked`, `consultation_link_clicked`, `live_room_opened`）を API 経由で送信。

### 4.2 方針B: 完全永続化拡張（段階2）

変更対象（予定）:

- `src/oracle_app/persistence/postgres.py`
- `src/oracle_app/persistence/hybrid_store.py`
- `src/oracle_app/store.py`（必要最小限の拡張）
- `src/oracle_app/models.py`（必要時のみ）
- `src/oracle_app/orchestrator.py`
- `scripts/init_persistence.py`
- `scripts/migrations/*`（新規）

実装方針:

- PostgreSQL テーブルに `users/subscriptions/ticket_wallets/announcements/inquiries` を追加。
- `HybridStore` で `update_user/get_or_create_user/list_users/create_announcement/list_announcements/add_inquiry/list_inquiries` を上書きし、InMemory互換を維持した dual-write / read-through を実装。
- InMemory はローカル・テスト向け、永続化有効時は PostgreSQL/Redis を主経路とする設計を明文化。
- マイグレーションSQL（up/down）を追加し、適用・ロールバック手順をスクリプト化。

### 4.3 方針C: CI・監査ログ・監視の最小着手

変更対象（予定）:

- `.github/workflows/backend-ci.yml`（新規）
- `src/oracle_app/api.py`
- `src/oracle_app/schemas.py`
- `src/oracle_app/store.py` / `persistence/postgres.py`（監査ログ保存が必要な場合）
- `docs/*`（監査ログ設計メモ、監視設定一覧）

実装方針:

- CI: pytest + smoke_test + init_persistence を自動実行。
- 監査ログ: 認証・課金・管理操作を「誰が・いつ・何を」追跡可能な形で記録。
- 監視: 既存 `/health` に加え、監視向け詳細ヘルス（依存先状態）を追加し、閾値を docs に明記。
- 監査ログ文言・運用ログ文言は日本語で統一。

### 4.4 影響分析（実装時に注意）

- モバイル画面
  - U-12/U-14/U-15/U-16 の本実装により導線クリック時の API 通信が増加。
- API
  - 追加は後方互換（既存エンドポイントの契約は維持）。
- 課金/履歴
  - 永続化拡張により再起動後の課金状態・履歴整合が向上。
- 管理画面
  - 監査ログ一覧API追加時は admin 側の将来画面拡張余地が増える。
- 通知/分析
  - 外部導線タップ計測を実装し、KPI捕捉漏れを削減。

### 4.5 最小変更原則

- 既存責務（api/service/store/persistence）を維持し、過剰な新規層を作らない。
- 既存 `app_state` 拡張を優先し、並立状態管理を追加しない。
- 既存 config を優先使用し、不要な設定値乱立を回避する。
