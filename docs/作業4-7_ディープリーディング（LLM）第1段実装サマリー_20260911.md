### 2.1 代わりに移植したもの

先行アプリは生成AIを採らない代わりに、**人のレビューに頼らず機械で守る**禁止語を置き、
全生成文へ当てていた（`Constants.FORTUNE_FORBIDDEN_ASSERTIONS` 18語・`ReadingDiversityTest` が検査）。

これは本方針 §3.6 の「断定的な助言語の検査」そのもので、しかも実運用で揉まれた語彙である。
∴ **18語をそのまま移植**し、マスタの新シート `禁止表現マスタ` に置いた（区分・理由つき）。

| 区分 | 語 |
|---|---|
| 健康 | 治りま／治る／完治／病気が／健康になり |
| 金銭 | 儲か／損をし／収入が増え／金運が上がり／必ず得 |
| 恐怖訴求 | 不幸／災い／祟／呪 |
| 断定 | 必ず／絶対／危険です／警告 |

先行アプリとの違いは当て先である。あちらは**内蔵エンジンの全文**に、
本アプリは**外部生成の結果**に当てる（内蔵エンジンにも当てられる形にしてある）。

## 4. 設計上の約束（なぜそうしたか）

- **失敗したら消費しない**: 生成成功かつ検査通過の後に `consume_for_spread` を呼ぶ。
  返却処理を作らないための順序で、順序そのものが仕様。
- **2回目は再生成しない**: `deep_text` があれば即返す。二重課金と文章の揺れを同時に防ぐ。
- **握り潰さない**: `none / applied / unavailable / failed / rejected` を持つ。
  「押していない」「準備中」「失敗」を同じ表示にしない。
- **課金の分岐を増やさない**: マスタの1行で済ませ、`BillingService` に手を入れていない。
- **送信内容は1メソッドに閉じる**: プロンプトは `InterpretationEngine` が組み立て、
  サービス層は素の文字列を継ぎ足せない。利用者IDが混ざらないことをテストで固定した。
- **同意が無ければ実行しない**: `User.deep_reading_consented_at` が None なら 403。

## 8. 3大リスクの最終サマリー

### 金銭・課金

1. 二重課金 → 冪等化で塞いだ（テスト4が固定）
2. 失敗時の消費 → 成功・検査通過の後に消費（テスト3・5・6が固定）
3. 費用の暴走 → 入力6000字・出力2400字の上限を設定に持つ（超過は `rejected`）

### システム

1. 応答待ちで画面が固まる → タイムアウト既定20秒。設定で変更可
2. 事業者側の障害 → `failed` として見せる。本文は内蔵エンジンのまま残る
3. 個人情報の混入 → 組み立てを1メソッドへ限定し、送信内容をテストで固定

### 運用

1. ポリシー未改定のまま公開 → Ver.1.2 で改定済み。事業者名の追記を未対応事項1・2に明記
2. 本番で `noop` のまま → 起動時に警告（既存2連携と同じ）。画面は「準備中」
3. 文章の品質低下 → 禁止表現で弾いたら内蔵の本文へ戻す。採用・却下をログへ
