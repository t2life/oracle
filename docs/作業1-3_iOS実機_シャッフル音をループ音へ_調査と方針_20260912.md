## 0. 結論

オーナーのご質問「シャッフル中は別の音源に変更を検討すべきか」への回答は **はい** である。
ただし**音源の差し替えだけでは直らない**。原因が2つあり、両方を変える必要がある。

| 原因 | 内容 | 対応 |
|---|---|---|
| 鳴らし方 | 0.28秒の短い音を指の動きに合わせて**繰り返し鳴らし直す**作りのため、音と音の間に必ず隙間ができる | シャッフル中は**切れ目なく鳴り続ける音（ループ）**を1本流す |
| 音源 | `shuffle.wav` は正式素材が届くまでの**仮の合成音（ホワイトノイズ）**で、音色そのものが雑音に近い | ノイズではない音色の**ループ音源**に替える（試聴用に3案を用意） |

## 1. 作業1: 事実確認（前回の修正が効かなかった理由）

### 1.1 実機の結果

前回の修正（同じ音が鳴っている間は打ち切らない）を入れたビルドで、オーナー確認は
**「途切れて雑音に聞こえる」**（NG）。修正版のビルドが実機に入っていたことは、
アプリ本体の作成時刻（ソース更新より後）で確認済み。

### 1.2 鳴らし方の構造 — 隙間が必ずできる

`mobile_app/lib/features/shuffle/presentation/shuffle_screen.dart` L118-132 は、
指が動いている間 **170ms を超えるごと**に鳴らす。前回の修正後は、鳴っている最中の呼び出しは捨てられるため、
次に鳴るのは「鳴り終わった後の最初の170ms刻み」になる。

| 時刻 | 起きること |
|---|---|
| 0ms | 鳴らす（0.28秒の音） |
| 約170ms | まだ鳴っている → 捨てる |
| 280ms | 音が終わる |
| 約340ms | 次を鳴らす |

∴ 音と音の間に**毎回 約60ms以上の無音**が入り、さらに iOS は鳴り始めに AVPlayer の再開の遅れが乗る
（前回方針書 §2.1。iOS では低遅延モードが効かない）。短い音を繰り返す作りである限り、
**刻みをどう調整しても iOS では「途切れ」が残る**。

### 1.3 音源 — 仮の合成ノイズ

`scripts/generate_sound_assets.py` の冒頭に「正式な効果音素材が未提供のため…プレースホルダ効果音（WAV）を合成」とある。
`gen_shuffle()` は `_noise_swish(0.28, 0.42)`＝**乱数ノイズを軽くならした音**である。
短く区切られて聞こえるほど「雑音」の印象が強くなる。

### 1.4 既存の仕組みで使えるもの

| 既存 | 内容 |
|---|---|
| `SoundService.playAmbience` / `stopAmbience`（`sound_service.dart` L82-101） | 効果音とは**別のプレイヤー**で長い音を鳴らす入口。現在はオープニング（`splash_screen.dart` L44・L61）だけが使う |
| `SoundService.toggle()` | 音を OFF にすると `stopAmbience()` を呼ぶ（L56-60）。ループにしても OFF で止まる |
| `audioplayers` の `ReleaseMode.loop` | 繰り返し再生の指定。iOS 版は「終わったら先頭へ戻して再開」で実現している（`audioplayers_darwin` 6.5.0 `WrappedMediaPlayer.swift` `onSoundComplete`） |
| `scripts/generate_sound_assets.py` | 乱数の種が固定で、**実行すると既存の6ファイルがバイト単位で同じものになる**（本日確認）。1ファイルだけ作り替えても他は変わらない |

## 3. 作業3: 修正方針

### 3.1 鳴らし方 — シャッフル中は1本のループ

- **開始**: シャッフル段階（`_ShufflePhase.shuffling`）で**最初に指が触れたとき**に1回だけ
  `SoundService.instance.playAmbience(OracleSound.shuffle, loop: true)`
- **継続**: 指を離しても、シャッフル完了までは鳴り続ける（止めたり再開したりすると、また途切れの原因になるため）
- **停止**: `_completeShuffle()` で集める音（`whoosh`）の直前に `stopAmbience()`。途中でタブ移動・やめる等で画面を離れたときは `dispose()` で `stopAmbience()`
- **振動**: 現行どおり 170ms ごと（音とは切り離す）

```diff
--- a/mobile_app/lib/core/audio/sound_service.dart
+++ b/mobile_app/lib/core/audio/sound_service.dart
@@
-  /// オープニング等の長尺環境音（多重再生しない）。
-  Future<void> playAmbience(OracleSound sound) async {
+  /// オープニング等の長尺環境音（多重再生しない）。
+  ///
+  /// [loop] が true のときは [stopAmbience] まで繰り返す（シャッフル中の音）。
+  /// 短い音を繰り返し鳴らし直すと、iOS では音の間に隙間ができて途切れて聞こえるため
+  /// （2026-09-12 iOS実機）、続けて鳴らしたい音は1本のループにする。
+  Future<void> playAmbience(OracleSound sound, {bool loop = false}) async {
     if (!enabled.value) {
       return;
     }
     try {
       await _ambiencePlayer.stop();
+      await _ambiencePlayer.setReleaseMode(
+        loop ? ReleaseMode.loop : ReleaseMode.stop,
+      );
       await _ambiencePlayer.play(AssetSource('sounds/${sound.fileName}'));
```

`shuffle_screen.dart` は、ループを開始済みかを持つ `bool` を1つ足し、上記の開始・停止を置く。
指の動きごとの `SoundService.instance.play(OracleSound.shuffle, ...)` の行は削除する。

### 3.2 音源 — ノイズではない音色のループ（オーナーが選ぶ）

試聴用に3案を合成した（いずれも 6.0秒で継ぎ目なくつながる。試聴ファイルは3回繰り返した18秒版）。
既存の効果音と同じく**仮の音**で、正式素材が届いたら同名ファイルを差し替えるだけで済む。

| 案 | 音色 | 向き・不向き |
|---|---|---|
| A 神楽鈴風 | 高い鈴の音が不規則にしゃらしゃらと鳴り、ごく薄い低音が支える | 日本神話の世界観に合う。動きのある「儀式」感。鈴の数が多いと賑やかに感じる可能性 |
| B 風のうねり | 低くならした風音が3秒周期でゆっくり揺れ、鈴がまばらに鳴る | 静かで神秘的。ただし風音はノイズが元なので、**雑音と感じる可能性は残る** |
| C 低音の持続音 | 低い和音が息をするように揺れ、高い倍音がかすかに明滅する | 最も静かで、雑音感はない。動きの手応えは弱い |
| D 正式素材 | オーナーが用意する音源（実録のカード音・神楽鈴など、利用許諾のあるもの） | 本番品質。ファイルを `shuffle.wav` として置くだけで差し替わる（4〜8秒程度・先頭と末尾がつながる音が望ましい） |

選ばれた案を `gen_shuffle()` に反映して `shuffle.wav` を作り直す（D の場合は生成せずファイルを置く）。

### 3.3 採らなかった案

| 案 | 採らない理由 |
|---|---|
| 音源だけ替えて、今の「指の動きごとに鳴らす」作りを残す | §1.2 の隙間が残り、iOS では途切れる |
| 指が動いている間だけ鳴らし、離したら止める | 短く触るたびに開始・停止が起き、同じく途切れる |
| 音量を指の勢いに合わせて変える | 手応えは増すが、iOS へ毎フレーム音量変更を送ることになる。まず鳴らし方を直し、必要なら次の段で検討 |
| 効果音用のプレイヤーでループする | 画面のタップ音等が同じプレイヤーを止めてしまう。長い音は既存の環境音プレイヤーに分けている設計に従う |

### 3.4 リスクと確認

| 項目 | 内容 |
|---|---|
| ループの継ぎ目（iOS） | iOS 版 `audioplayers` は終わるたびに先頭へ戻して再開するため、**6秒ごとにごく短い隙間が出る可能性**がある。実機で確認し、気になる場合は音源を長くする（10秒程度） |
| Android | 同じコードのため Android も同じ鳴り方に変わる。Windows 側の実機で確認をお願いする |
| 音 OFF（スピーカーアイコン） | OFF 時は `playAmbience` が何もしない。鳴っている途中で OFF にすると既存の `toggle()` が止める |
| 画面離脱 | `dispose()` で止めるため、シャッフル途中でホームへ戻っても鳴り続けない |
