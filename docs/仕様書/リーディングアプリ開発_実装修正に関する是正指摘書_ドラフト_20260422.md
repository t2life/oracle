# リーディングアプリ開発 実装修正に関する是正指摘書（ドラフト）

## 1. 文書の目的

本書は、次の3文書で定義された要件と、2026-04-22 時点の実装内容との差分を明確化し、
是正と追加対応を要請することを目的とする。

- リーディングアプリ開発 詳細仕様書
- リーディングアプリ開発 追補仕様書
- リーディングアプリ UI設計フェーズ資料

対象は、本プロジェクトの実装（作業4〜7）を担当した開発AIと、
それを管理する人間開発者である。

## 2. 現時点の評価

現行成果物は、バックエンドAPIを中心としたMVP実装としては前進がある。
一方で、仕様書が要求する全体スコープへの準拠は不十分である。

### 2.1 評価結論

- 評価: バックエンドMVPとしては有効
- 判定: 仕様書どおりの開発完了とは認定不可
- 理由: モバイルUI、管理画面、永続DB、通知運用、分析、外部導線が未充足

### 2.2 実装済みの主要範囲

- バックエンドAPIの一部実装
- 占いフロー（開始、シャッフル判定、山選択、カード確定、結果取得）
- 無料制限・有料差分の一部ロジック
- 簡易課金判定（インメモリ）
- 通知トークン登録
- 問い合わせ受付
- 単体テスト6件

### 2.3 未充足の主要範囲

- iOS/Androidアプリ本体（Flutter等）
- 管理画面（A-01〜A-08）の実装
- 認証手段の完全実装（Apple/Google連携）
- 永続DB（PostgreSQL）とキャッシュ（Redis）
- 通知運用（予約配信、セグメント、A/B配信、効果測定）
- 分析基盤（analytics_events、KPI収集）
- 外部導線管理（ショップ、鑑定、VTuber）

## 3. 是正が必要な主なポイント

### 3.1 スコープ認識のズレ

【指摘】

現成果物は `src/oracle_app` のAPIとサービス群が中心であり、
仕様が定義するモバイルアプリ本体と管理画面の実装が確認できない。

【要求】

- 今回実装の対象スコープ（実施済み）を明示すること。
- 仕様全体スコープとの差分を表で提示すること。
- 本成果物を「バックエンドMVP段階」として再定義すること。

### 3.2 認証・会員機能の深度不足

【指摘】

- `/auth/login` は存在するが、入力は `user_id` のみで簡易実装。
- `/auth/apple`, `/auth/google` は未実装。
- 退会、購入復元、会員状態遷移の運用フローが未実装。

【要求】

- 認証の実装済み/未実装と、状態遷移の定義を提出すること。
- Apple/Google認証を優先度高で計画に組み込むこと。

### 3.3 管理画面の未実装

【指摘】

仕様で要求される管理画面機能（カード管理、通知管理、KPI等）に対応する
管理画面フロントエンド実装が確認できない。

【要求】

- A-01〜A-08 画面IDごとの実装計画を提示すること。
- Admin API と管理画面UIの責務分担を明示すること。

### 3.4 DB構成の差異

【指摘】

現在は `InMemoryStore` による揮発実装であり、
仕様想定の PostgreSQL/Redis 構成に未到達。

【要求】

- インメモリ採用理由と移行前提を文書化すること。
- データモデル対応表を作成し、永続化設計へ接続すること。

### 3.5 課金機能の運用不足

【指摘】

チケット/サブスクの簡易判定はあるが、
ストア連携検証、失効、猶予、復元の実装が不足。

【要求】

- 課金要件のカバー範囲と未対応範囲を明示すること。
- 段階リリース計画に運用課金の完成条件を定義すること。

### 3.6 通知・お知らせ機能の不足

【指摘】

現状はトークン登録と告知取得に限定され、
配信運用（予約、セグメント、AB、効果測定）は未実装。

【要求】

- 通知機能のv1対象を明確化すること。
- 配信運用機能の実装順序を提示すること。

### 3.7 UI資料とのトレーサビリティ欠如

【指摘】

画面ID（U-xx/A-xx）に対する実装状況一覧が未提示であり、
UI項目定義とAPIの接続状況が追跡できない。

【要求】

- 画面IDごとの実装済み/未実装一覧を提出すること。
- 実装済み画面は使用API・スキーマ・モデルを明記すること。

### 3.8 テスト観点の限定

【指摘】

6件のテスト通過は確認できるが、仕様要件全体への受入証明には不足。

【要求】

- テスト観点マトリクスを提示すること。
- 仕様要件とテストケースの対応を明示すること。

## 4. 是正および追加対応の要請

次の成果物を追加提出すること。

1. 仕様書対実装の対応表
2. スコープ再定義（MVP範囲とフルスコープの分離）
3. 不足機能の実装計画（優先度・段階・完了条件）
4. 画面IDトレーサビリティ
5. テスト観点マトリクス

## 5. 結び

現成果物は、バックエンドMVPとしての前進は認められる。
ただし仕様書の全体要求に対しては不足があり、
「仕様どおりの開発完了報告」としては受入不可である。

本指摘書に基づき、スコープ再明示、対応表提出、実装計画提示を行い、
次フェーズの共通認識を再確立することを要請する。
