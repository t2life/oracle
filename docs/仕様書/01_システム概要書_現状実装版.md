## 2. 本書の目的

既存の`docs/`配下には、企画書由来の要求仕様（詳細仕様書・追補仕様書）と、複数ラウンドにわたる是正監査記録（`作業1-3_*`・`作業4-7_*`・`是正指示書*`・`開発会社向け*`）が蓄積されている。これらは断続的な監査の記録であり、**最新時点でシステムが実際にどう動くか**を1枚で把握できる文書が存在しなかった。

本書はその欠落を埋め、以降の`02`〜`12`番の詳細文書の入口となる。

## 3. 現状のシステム構成（3系統）

```text
system/
├── src/oracle_app/      … バックエンドAPI（Python / FastAPI）
├── mobile_app/          … モバイルアプリ（Flutter / Dart）
├── admin_app/           … 管理画面（Next.js / TypeScript / React）
├── scripts/             … 起動・マイグレーション・スモークテスト補助
├── tests/                … pytestテスト（4ファイル）
└── docs/                 … 仕様書・是正記録
```

過去の監査文書（2026-04-22時点）では「モバイルアプリ本体・管理画面は実装ファイルなし」と判定されていたが、**その後の是正ラウンドで両方とも新規実装され、現在は3系統すべてに実体がある**。本書時点のファイル数は、`admin_app`23件・`mobile_app`31件・`src`47件・`tests`10件・`scripts`6件（フォルダファイル構成図.md準拠）。

## 4. システム構成図（現状）

```text
[ Flutter モバイルアプリ (mobile_app/) ]
        │  http (ApiClient, 既定 http://127.0.0.1:8000)
        ▼
[ FastAPI バックエンド (src/oracle_app/) ]
   ├─ api.py … 32エンドポイント（05_API仕様書.md 参照）
   ├─ services/ … Auth/Content/Billing/Reading/Notification/Inquiry/Analytics/Link/Admin の9サービス
   ├─ orchestrator.py … DIコンテナ（ServiceContainer）組立
   ├─ store.py … InMemoryStore（既定バックエンド）
   └─ persistence/ … HybridStore・PostgresPersistence・RedisCache（任意有効化）
        │
        ├─ PostgreSQL（任意・ORACLE_POSTGRES_ENABLED）
        └─ Redis（任意・ORACLE_REDIS_ENABLED）

[ Next.js 管理画面 (admin_app/) ]
        │  fetch (lib/api.ts, X-Admin-Token ヘッダー認証)
        ▼
   同一バックエンドAPI（/admin/* エンドポイント群）
```

## 6. 未充足・要監督の領域（詳細は`11_今後の開発ロードマップ.md`）

- 課金はサーバー側の受領検証ロジックはあるが、Apple/Google公式レシート検証API連携は未接続（`receipt_id`の形式チェックのみ）。
- 通知配信は「作成・一覧・ディスパッチ」までは実装済みだが、実際のFCM/APNs送信連携は未接続。
- 管理者の権限ロール（`AdminRole.permissions`）は定義のみで、エンドポイント側の権限別アクセス制御は未実施（トークンの有無のみ判定）。
- プライバシーポリシー・特定商取引法表記等の法務文書が未作成（`09_プライバシーポリシー.md`で着手）。
- PostgreSQL/Redisの実機接続検証（ステージング相当）は`init_persistence.py`のローカル確認のみで、本番同等環境での検証は未実施。

## 7. 用語整理

| 用語 | 意味 |
|---|---|
| 宣託 | 1回のオラクルカード占い体験（テーマ選択→シャッフル→山選択→カード確定→結果） |
| 山（パイル） | シャッフル後にカード束を分割した3つのグループ（`pile_index` 1〜3） |
| ロンの部屋 | VTuber「ロン」の配信・アーカイブ・限定告知を扱う導線画面（U-14） |
| HybridStore | InMemoryStoreを継承し、PostgreSQL/Redisが有効な場合はそちらを優先経路として使うストア実装 |
| ORACLE_RUNTIME_MODE | `local`/`staging`/`production`。staging/production では InMemory 使用と初期化失敗時の自動フォールバックを禁止するガードが働く |
