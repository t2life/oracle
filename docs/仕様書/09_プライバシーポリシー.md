## 2. 収集する情報（実装ベース）

現行実装で実際に保持し得る個人関連情報を、モデル定義（`models.py`）に基づき棚卸しする。

| 分類 | 項目 | 保持箇所 | 用途 |
|---|---|---|---|
| アカウント識別子 | `user_id` | `User` | 会員識別・全機能の紐付けキー |
| 認証情報 | `provider`, `provider_user_id`, `email` | `AuthAccount` | Apple/Google/メール認証の紐付け |
| プロフィール | `display_name`, `locale` | `Profile` | 表示名・言語設定 |
| 利用状況 | `visit_count`, `created_at`, `updated_at` | `User` | 継続率等のKPI算出 |
| 占い履歴 | `theme_id`, `deck_id`, `card_id`, `summary`, `full_text` | `HistoryItem` | 履歴閲覧機能（無料は直近3件、有料は無制限） |
| 課金状態 | `plan`, `tickets`, `subscription_expires_at` | `User` | 権限判定・表示制御 |
| 決済参照情報 | `receipt_id`, `restore_receipt_id`, `product_code` | API受信のみ（重複判定用に`_used_receipts`で保持） | 二重課金防止 |
| 通知トークン | プッシュ通知用トークン文字列 | `store._notification_tokens` | プッシュ配信の宛先 |
| 通知設定 | `push_enabled`, `reminder_enabled`, `campaign_enabled` | `NotificationSetting` | 通知種別ごとのオプトイン管理 |
| 問合せ内容 | `category`, `body`, `email` | `Inquiry` | サポート対応 |
| 行動イベント | `event_name`, `properties` | `AnalyticsEvent` | KPI分析（DAU、転換率等） |
| 操作監査ログ | `actor_type`, `actor_id`, `action`, `detail` | `AuditLog` | 不正利用調査・運用監査 |

## 3. 収集しない情報（現状実装の確認事実）

- 生年月日・性別・住所等の属性情報は、いずれのモデルにも定義がなく収集していない。
- クレジットカード番号等の決済カード情報は保持しない（ストア決済SDK・レシートIDのみを扱う想定）。
- 位置情報を収集する機能は現行モデルに存在しない。

## 4. 利用目的

1. 占いサービス（宣託）の提供・履歴保存・結果表示
2. 会員管理（ログイン状態・プラン・チケット残高の維持）
3. 課金処理（レシート検証・復元・二重処理防止）
4. プッシュ通知・アプリ内お知らせの配信
5. 問合せ対応
6. サービス改善のための行動分析（KPI集計）
7. 不正利用防止・セキュリティ監査（監査ログ）

## 5. 第三者提供・委託

| 連携先 | 提供情報の範囲 | 目的 |
|---|---|---|
| Apple（Sign in with Apple / App Store決済） | `provider_user_id`, レシート情報 | 認証・課金検証 |
| Google（Google Sign-In / Google Play決済） | `provider_user_id`, レシート情報 | 認証・課金検証 |
| プッシュ通知基盤（FCM/APNs、詳細仕様書21章想定） | 通知トークン | プッシュ配信 |
| 分析基盤（詳細仕様書20章 Firebase Analytics + BigQuery想定） | 行動イベント（`event_name`, `properties`） | KPI分析 |

> 現状のコード実装では、上記外部連携（Apple/Google決済検証・FCM/APNs送信・外部分析基盤送信）は**API受け口のみ用意されており、実際の外部通信は未接続**（`11_今後の開発ロードマップ.md`参照）。本条項は接続完了時点で有効化される想定条項として記載する。

## 6. 保管期間・削除

- 会員がアプリ内から退会申請（詳細仕様書10.3章）を行った場合、`User`/`Profile`/`AuthAccount`/`HistoryItem`等の関連データを削除する運用を想定する。**現状、削除APIは未実装**であり、Phase 1（`11_今後の開発ロードマップ.md`）で対応予定。
- 監査ログ（`AuditLog`）は不正防止目的のため、会員本人からの削除依頼の対象外とし、別途保持期間ポリシー（案: 1年）を定める。**現状、保持期間の自動削除処理は未実装**。

## 7. ユーザーの権利

- 保有個人データの開示請求
- 訂正・削除請求
- 利用停止請求
- 第三者提供停止請求

問い合わせ窓口は`POST /inquiries`（アプリ内問合せ機能）を経由する運用とする。

## 8. Cookie等のトラッキング技術

現行はネイティブモバイルアプリ・管理画面（Next.js）が対象であり、Webブラウザ向けCookieポリシーは管理画面ログインセッション（`localStorage`のトークン保持）に限定される。管理画面の`localStorage`保持内容は管理者トークンのみで、エンドユーザーの個人情報は含まない。

## 9. 未成年の利用方針

詳細仕様書24章に「未成年利用方針」の明示が求められているが、主ターゲットは30〜80代女性（詳細仕様書4.1章）であり、現行実装に年齢確認機構は存在しない。ストア審査対応として、年齢確認またはレーティング設定の方針を別途確定する必要がある。
