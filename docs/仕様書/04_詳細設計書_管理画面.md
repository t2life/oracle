## 3. 認証方式

- `POST /admin/login`（email, password）でトークンを取得し、以降の管理APIは`X-Admin-Token`ヘッダーで認可する。
- トークンはブラウザの`localStorage`に保持（`lib/api.ts`）。
- バックエンド側`AdminService.require_admin(token)`がトークン有効性と管理者の`is_active`を検証。

> 現状、`AdminRole.permissions`（ロール別権限リスト）はモデル定義のみで、各エンドポイントでの権限別アクセス制御（例: Content AdminはKPI閲覧不可、等）は未実装。トークンの有無のみで全管理APIにアクセス可能な状態であり、`14. 管理画面仕様 §14.2 権限ロール`（詳細仕様書）に対しては部分準拠。

## 4. ページ別実装内容

| ページ | 画面ID | 内容 | 使用API |
|---|---|---|---|
| LoginPage | A-01 | メール・パスワードでログイン、トークン取得 | `POST /admin/login` |
| DashboardPage | A-02 | KPIサマリ表示（users_total, inquiries_total, announcements_total, campaigns_total, reading_completed, ticket_purchased, subscription_started） | `GET /admin/dashboard` |
| ThemesPage | A-03 | テーマ一覧・公開状態確認 | `GET /admin/themes` |
| DecksPage | A-03 | デッキ一覧・公開状態確認 | `GET /admin/decks` |
| CardsPage | A-03 | カード一覧・検索 | `GET /cards`（deck_id・q対応） |
| AnnouncementsPage | A-04 | お知らせ一覧・新規作成 | `GET/POST /admin/announcements` |
| CampaignsPage | A-05 | 通知キャンペーン一覧・作成・配信実行 | `GET/POST /admin/campaigns`, `POST /admin/campaigns/{id}/dispatch` |
| UsersPage | A-06 | 会員一覧（プラン・チケット残数・登録日） | `GET /admin/users` |
| InquiriesPage | A-07 | 問合せ一覧 | `GET /admin/inquiries` |
| AnalyticsPage | A-08 | イベント別カウント（app_open等16種） | `GET /admin/analytics/kpi` |

## 5. APIクライアント（lib/api.ts）

管理画面専用の型定義（`AdminLoginResponse`/`DashboardResponse`/`UserSummary`/`InquirySummary`/`Announcement`/`Campaign`/`ThemeAdmin`/`DeckAdmin`/`Card`/`KpiResponse`）と、対応する`fetch`関数（`adminLogin`, `fetchDashboard`, `fetchUsers`, `fetchInquiries`, `fetchAnnouncements`, `createAnnouncement`, `fetchThemes`, `fetchDecks`, `fetchCards`, `fetchCampaigns`, `createCampaign`, `dispatchCampaign`, `fetchKpi`）を提供する。全てトークンを引数に取り、`X-Admin-Token`ヘッダーへ設定する。

## 6. ナビゲーション構成（components/nav-shell.tsx）

サイドバーからA-02〜A-08の各ページへ遷移可能。A-01（ログイン）は未認証時の入口として常に到達可能。ロール別のメニュー出し分けは未実装（全ログイン管理者に同一メニューを表示）。

## 7. 未実装・要拡張事項

- 管理者ロール別のUI出し分け・APIアクセス制御（Super Admin/Content Admin/CS Support/Analyst の4区分は詳細仕様書14.2で定義済みだが、実コードでの分岐は未実装）。
- 2要素認証（詳細仕様書14.1「2要素認証推奨」）は未実装。
- カード/デッキ/テーマの**編集・公開切替の書き込みAPI**（現状は閲覧系APIが中心。作成系は`POST /admin/announcements`と`POST /admin/campaigns`のみ）。
- KPIダッシュボードのDAU/MAU・継続率等（詳細仕様書22章の全項目）は`AnalyticsRules.required_events`のカウントに限定され、比率指標（転換率・継続率）は未算出。
