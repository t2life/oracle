## 2. 基本方針（結論）

**ストア申請時点および初期運用（0〜6ヶ月）では広告を掲載しない。**
成長期（6〜12ヶ月）にリワード広告のみを限定導入し、安定期（12ヶ月以降・DAU 5,000以上）に
バナー広告の追加を検討する。**インタースティシャル（全画面割込）広告は全期間で不採用**とする。

理由の要点（詳細な試算は根拠文書§6を参照）:

1. 本アプリは世界観・神聖性がブランド価値の中核であり、初期の広告掲載は没入感とレビュー評価を毀損する。
2. 課金（チケット/サブスク）の転換率最適化が先決であり、広告は課金動機を希釈する。
3. 段階導入（リワード→バナー）は、課金と広告の二本立て収益を両立させる業界の定石である。

## 3. フェーズ定義

| フェーズ | 期間の目安 | 広告方針 | 主要KPI |
|---|---|---|---|
| Phase 1 | ストア申請〜6ヶ月 | **広告なし** | DAU、課金転換率、レビュー評価 |
| Phase 2 | 6〜12ヶ月 | リワード広告のみ（オプトイン。「広告を見て1回追加占い」等） | リワード視聴率、課金転換率の変化、満足度 |
| Phase 3 | 12ヶ月以降 | バナー追加を条件付き検討（下記移行条件） | 広告RPM、離脱率、ARPU |

Phase 3 への移行条件（全て満たす場合のみ）:

- DAU 5,000 以上
- 課金転換率の測定が安定している（リワード導入による悪化が -0.1pt 以内で収束）
- レビュー・問い合わせで広告への強い拒否反応が観測されていない

## 4. 実装原則（Phase 2以降で適用）

1. リワード広告はユーザー選択制（オプトイン）とし、強制視聴を作らない。
2. 有料プラン（サブスク/チケット保有者）には広告を表示しない。
3. 広告カテゴリはAdMob設定で制限し、世界観と衝突する広告（ゲーム・出会い系等）を除外する。
4. 占い結果表示の直後に全画面広告を挟む実装は禁止（インタースティシャル不採用の再確認）。
5. iOS ATT・GDPR・個人情報保護法に基づく同意管理を広告SDK導入と同時に実装する。
6. 広告関連APIを追加する場合は、`/ads/rewarded-event`（視聴完了記録）・`/ads/config`
   （表示設定取得）の2本を起点に設計し、`05_API仕様書.md`へ追記する。

## 5. Phase 1 のアクション（現行フェーズ）

- 広告SDKは導入しない（`pubspec.yaml`へ広告依存を追加しない）。
- Google AdMob アカウントの登録・審査だけを事前準備として進めてよい（コード変更なし）。
- 分析イベント（`paywall_viewed`、`ticket_purchased`、`subscription_started`等）の蓄積を優先し、
  Phase 2 判断の基礎データを揃える（分析イベントのPostgres化＝ロードマップA-3が前提）。
