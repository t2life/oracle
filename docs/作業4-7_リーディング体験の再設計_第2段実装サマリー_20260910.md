# 作業4-7 リーディング体験の再設計 第2段（モバイルUI）実装サマリー

作成日: 2026-09-10

## 1. 対象

承認済み方針（`作業1-3_リーディング体験の再設計_調査と修正方針_20260910.md`）の
残作業のうち、**①種別分岐・②テーマ＋相談内容・複数枚のカード選択・結果のポジション表示**を
モバイルアプリへ実装した。サーバー側（API・スプレッド定義・複数枚の状態機械・
オフライン合成器）は第1段で完了しており、本段はその配線と画面である。

## 2. 導線（承認どおりの順序）

```text
ホーム「占う」オーブ
  └ 種別分岐（本日の託宣／リーディング）※プランとチケット残数をここで提示
       ├ 本日の託宣 → デッキ選択 → テーマ選択（グリッド＝現状維持）
       └ リーディング → デッキ選択 → 種別（3枚/5枚/7枚/フリー）
                                  → テーマ（プルダウン）＋相談内容（3000字）
  → シャッフル → 山選択 → カード選択（必要枚数ぶん）→ 結果
```

## 4. 設計上の約束

- **枚数・必要チケット・対象プランは画面に持たない。** すべてスプレッド定義（`DB/*.xlsx` →
  `interpretation_content.json`）が決め、画面は `available` / `unavailable_reason` を出すだけ。
  枚数を増やす・料金を変えるといった変更はマスタの更新で完結する。
- **同じ判定を2か所に書かない。** 無料枠・チケット・対象プランの事前判定は
  サーバーとオフラインエンジンの両方に必要だが、いずれも同じ規則（`start_session` と同値）に
  そろえ、テストで固定した。
- **「選んでから弾かれる」を作らない。** 使えない導線は最初の画面で理由まで見せる。
