# 作業4-7 ディープリーディング（外部AI）の取りやめ

作成日: 2026-09-11
決定: **外部AIは使わない（A案）**

## 1. なぜ取りやめたか

実装が `mode=noop` まで到達した段階で、オーナーより
「**なぜAI事業者が必要か。アプリ自体にAI機能はないはず**」との指摘を受け、
機能そのものを見直した。確認した事実は次のとおり。

| 確認 | 結果 |
|---|---|
| 仕様書での定義 | `詳細仕様書`・`追補仕様書`・`UI画面遷移仕様書`・`マネタイズ方針書` に**1件もヒットなし** |
| 実装の実体 | ボタンの文言のみ。押すとプラン購入画面へ飛ぶだけだった |
| アプリのAI利用 | **無い**。結果の文章は内蔵エンジン（マスタ＋テンプレート＋決定的ハッシュ）が組み立てる |
| 先行アプリ | 同じ問いで「生成AIによる文章生成」を意図的に見送っている（`docs/150 §4.8`） |

∴ 外部AIが必要だったのは**この機能のためだけ**であり、機能自体が仕様に無かった。
第1段で内蔵エンジンの文章を作り込んだ結果、オフラインでも同じ品質の文章が出る。
ここに外部依存を足して得られる差分に対し、法務・審査・費用・運用の対価が釣り合わない。

## 2. 取りやめの範囲（実装の撤去）

コミット前だったため、`git checkout` で以下を元に戻した。

| 撤去 | 対象 |
|---|---|
| バックエンド | `services/llm_client.py`・`services/deep_reading_service.py`（削除）、`config.DeepReadingConfig`、`ReadingResult.deep_text` / `deep_reading_status`、`User.deep_reading_consented_at`、`POST /reading/{id}/deep`、`POST /account/deep-reading-consent`、分析イベント3件 |
| モバイル | `refineReading` / `setDeepReadingConsent`、結果画面の同意ダイアログと推敲表示、l10n 11キー |
| マスタ | `スプレッド定義` の `deep` 行（種別 `option`） |
| 文書 | プライバシーポリシー Ver.1.2 の「AI事業者」記述 → **Ver.1.3 で削除** |

**結果画面の「ディープリーディング」ボタンは、撤去せず現状のまま残している。**
オーナーより、同名で**カードを追加で引く深掘り機能**として再定義する案が出ており、
先に消すと再度追加することになるため。次の方針決定までの暫定措置である。

## 3. 残したもの（それ自体に価値がある）

### 禁止表現マスタ（18語）

先行アプリ（吉凶羅針盤）が生成AIを採らない代わりに置いた
`Constants.FORTUNE_FORBIDDEN_ASSERTIONS` を移植したもの。**規律ごと採用した。**

| 区分 | 語 |
|---|---|
| 健康 | 治りま／治る／完治／病気が／健康になり |
| 金銭 | 儲か／損をし／収入が増え／金運が上がり／必ず得 |
| 恐怖訴求 | 不幸／災い／祟／呪 |
| 断定 | 必ず／絶対／危険です／警告 |

当て先は**内蔵エンジンの託宣文**である（当初は外部生成の検査用だった）。
`InterpretationEngine.find_forbidden()` がマスタを見て検査し、
`tests/test_forbidden_expressions_20260911.py` が
**全44柱 × 全6テーマ（264通り）の生成文**を走査して禁止表現が出ないことを固定する。

素材（44柱.xlsx）へ不用意な語が入った時に、人のレビューではなく**テストが落ちて**気づける。
ストア審査と利用者の信頼の両方に効く。
