## 2. 語り口の改善

### 2.1 調査の結果 — 位置が時制を決める

3枚引き（過去・現在・未来）の解説では、**読み手は位置ごとに文末を変えている**。

| 位置 | 文末の型 | 意味 |
|---|---|---|
| 過去 | 「〜てきました」「〜だったのかもしれません」 | 済んだこと。断定しても害が小さい |
| 現在 | 「〜ています」「〜と言えますね」 | 今の状態。観察として述べる |
| 未来 | 「〜でしょう」「〜可能性が高いです」 | まだ決まっていない。**断定しない** |

つまり「断定を避ける」ことと「機械的になる」ことは同じではない。
**避けるべき断定は未来についてだけ**で、過去・現在はむしろ言い切ったほうが占い師らしい。
一律に「〜という意味合いが示されています」と逃げていたのが、機械的に見えた原因である。

出典: [3枚引きの読み方 | タロット教室](https://tarotkyoko.com/study-3card/)

### 2.2 実装 — `位置別語り口マスタ`（新規シート・21行）

| 列 | 内容 |
|---|---|
| ポジション名 | 過去／現在／未来／原因／結果／本音／建前／…（スプレッド定義の全ポジション） |
| 語り口1〜3 | `{name}` `{phrase}` `{meaning}` を差し込む定型文 |

1ポジションにつき3通り持ち、**カードIDとポジション名の md5 で選ぶ**。
同じカードが同じ位置に出れば必ず同じ文になる（再現性）。
利用者から見ると、カードや位置が変われば言い回しも変わる。

ポジションに語り口が無いときは従来の言い方へ落ちる（fail-soft）。

### 2.3 あわせて直したこと — 「鍵となる言葉:」

組み合わせ解釈の末尾に `（鍵となる言葉: A・B・C）` と出ていた。
これは**データの列名がそのまま文章に漏れていた**もので、ご指摘と同じ性質の傷である。

変更前:

```text
◯◯と△△の組み合わせは、□□、といった意味を帯びています。（鍵となる言葉: A・B・C）
```

変更後:

```text
◯◯と△△は「対立・調和」の関係にあります。□□。
この巡り合わせを言葉にするなら、A・B・Cです。
```

### 2.4 実際の出力

```text
【過去】速秋津日子神。流通業・物流、転職や業界転換の好機、
　　　　変化の波に乗るが、いまへ続く土台をつくってきました。
【現在】伊邪那岐命。あなたのまわりで、積極的な行動で仕事を創り出す、
　　　　決断と実行力が動き始めています。
【未来】天宇受売命。このまま進めば、表現力で成功、
　　　　魅力で顧客獲得へ向かう可能性が高いでしょう。

続いて、速秋津日子神と天宇受売命は「対立・調和」の関係にあります。
情熱と冷静のバランス、対立からの創造、調和の必要性。
この巡り合わせを言葉にするなら、バランス・調和・対立と統合です。
```

## 3. 深掘りリーディング

### 3.1 承認済みの仕様

| # | 決定 |
|---|---|
| 1 | 枚数は利用者に選ばせる（3／5／7。フリーは出さない） |
| 2 | 一律チケット5枚 |
| 3 | 月額有料プランは無制限 |
| 4 | **託宣と深掘りは履歴1件にまとめる** |

### 3.2 実装 — 起点のカードを引き継ぐ

深掘りは「託宣のカードをさらに読む」ものなので、
**起点のカードが1枚目に必ず座る**ようにした。

```text
本日の託宣（1枚）──▶ ディープリーディング
                      起点のカードが1枚目
                      残りを山から引く（起点は山から除く＝二度は出ない）
```

`origin_session_id` を開始要求からセッション・結果まで通し、
`ReadingService.start_session` で次の順に処理する。

1. 起点セッションの存在と**所有者**を確かめる（他人の託宣は深掘りできない）
2. チケットを消費する
3. 山から起点のカードを取り除き、1枚目として据える

**1と2の順序が要点。** 逆にすると起点が無いときにチケットだけ減る
（実装中に実際に踏み、20枚→15枚が戻らなかった）。

### 3.3 履歴を1件にまとめる（決定4）

結果を保存するとき、`origin_session_id` があれば
**起点の履歴を取り除いてから**深掘りの結果を積む（`delete_history_by_session`）。
マイページには「託宣＋深掘り」で1件だけ残る。

### 3.4 画面

| 画面 | 変更 |
|---|---|
| 結果 | 「ディープリーディング」ボタン。**1枚引きのときだけ**出す（深掘りの深掘りはしない） |
| 枚数選択 | フリーを外し、「起点のカードを引き継ぎます」と明示 |

オフライン（機内モード等）でも同じ引き継ぎが効くよう、`OfflineBackend` にも同じ手順を置いた。

## 7. 3大リスクの最終サマリー

### 占いとしての妥当性

1. 未来の断定 → 未来の語り口は全て「でしょう」「可能性」で、禁止表現マスタ18語の機械検査を通す
2. 語り口の単調化 → 1ポジション3通り。カードと位置の組で選ぶため、同じ文が続かない
3. 深掘りで矛盾した読み → 起点のカードが1枚目に座るので、託宣と地続きの読みになる

### システム

1. マスタ未整備 → 語り口が無ければ従来の言い方へ落ちる（fail-soft）
2. サーバーとオフラインの食い違い → パリティテストで一字一句を固定
3. 深掘りの不正な起点 → 存在と所有者を先に確かめ、**チケットを消費する前に**弾く

### 運用

1. 言い回しの調整 → マスタの定型文を直すだけ。アプリ更新は不要
2. 履歴の統合 → 起点を消してから積むため、二重に残らない
3. チケットの取り扱い → 深掘りは一律5枚。月額有料プランは消費しない
