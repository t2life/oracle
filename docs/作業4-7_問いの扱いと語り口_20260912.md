## 2. 原因と実装

### 2.1 原因は「問いを読まずに日付で選んでいた」こと

`services/interpretation_engine.py`

| 行 | 何が起きていたか |
|---|---|
| L156 | `質問タイプ分類`（19行）のキーワードに1語も当たらないと 状況＝`None` |
| L426 | `patterns[_stable_hash(date_key, theme_id) % len(patterns)]` ＝**日付でテンプレを選ぶ** |

「宝くじで1等を当てたい」は金運の判定語（収入・給料／投資・株／支出・節約）のどれにも当たらない。
∴ 「お金の使い方を見直す時期」は**問いを読んだ結果ではなく、日付が選んだだけ**だった。

### 2.2 `問いの扱いマスタ`（新規・6行）— 型だけを持つ

| 列 | 内容 |
|---|---|
| 区分 | `運任せ` / `分類外` |
| キーワード | 宝くじ・くじ・抽選・当選・当籤・一等・ギャンブル・賭け・馬券・競馬・競輪・競艇・パチンコ・スロット |
| 語り口 | 文脈テンプレの位置に置く段落の**型** |
| 助言 | アドバイス行の**型** |

差し込める語は**すべてカードの列**である（ご指摘への対応）。

| 差し込み | カードの出どころ |
|---|---|
| `{神名}` | `name_ja` |
| `{属性}` | `attribute` |
| `{エレメント}` | `element` |
| `{基本的意味}` | `basic_meaning` |
| `{キーワード}` | `keywords` |
| `{肯定的キーワード}` `{中立的キーワード}` `{行動提案ワード}` | `keyword_dict` |

`{属性}` `{エレメント}` は今回 `_fill_placeholders` へ追加した2語で、
残りは既存の文脈パターンDBと同じものである（新しい仕組みを作っていない）。

**カードが変われば文面の実体が変わる。型だけが共通。**

### 2.3 出し分け

| 状態 | 変更前 | 変更後 |
|---|---|---|
| 相談内容あり・状況が一致 | テンプレを出す | **同じ**（退行なし） |
| 相談内容あり・`運任せ` に該当 | 日付でテンプレを選ぶ | `運任せ` の型 |
| 相談内容あり・どれにも外れる | 日付でテンプレを選ぶ | `分類外` の型 |
| 相談内容なし（本日の託宣） | 日付でテンプレを選ぶ | **同じ**（問いが無いので無関係にならない） |

助言も同じ型から作るため、同じ語を二度言わない。

## 7. 3大リスクの最終サマリー

### 占いとしての妥当性

1. 当否の断定 → 禁止表現に当選断定4語を追加し、全44柱×2区分の生成文を機械走査（テスト14）
2. 突き放した印象 → 前置きを置かず、語り口と助言の2段で必ず受け止める。型はマスタで固定
3. 判定語の誤爆 → 「当たる」は採らず名詞のみ。「思い当たる」で誤爆しないことをテストで固定

### システム

1. マスタ未整備 → 区分が引けなければ従来どおり（fail-soft。テスト16）
2. サーバーとオフラインの食い違い → パリティ期待値に2ケース追加し一字一句を固定
3. 既存の問いへの退行 → 分類に当たる問いは経路が変わらないことをテストで固定（テスト3）

### 運用

1. 文面の調整 → マスタの型を直すだけ。アプリ更新は不要
2. 判定語の追加 → `問いの扱いマスタ` に行を足すだけ
3. 区分の追加 → 同シートに行を足す。コード変更は不要（`分類外` も同じ仕組み）
